- 使用指定 `py12` 解释器完成项目 `0.7.0` 可编辑安装；没有升级该环境其他项目的运行依赖。
- 隔离空 PostgreSQL 数据库执行全部迁移成功；用户当前库已升级到 `20261021_07`，只新增四张表。

关键行为测试包括：

1. 草稿等待时不发布报告、不参与租约恢复；批准前后调用计数不重置，人工等待不消耗剩余时间。
2. 拒绝、取消、过期摘要、相反重复决定阻止发布；重复批准只增加一次继续投递。
3. 修改请求创建同一后继任务、继承证据快照和父运行 ID；新任务再次复核。
4. 批准后证据发生变化仍拒绝发布。
5. 图检查点已经中断、任务表尚未转为等待时崩溃，租约恢复后不重做研究节点。
6. MCP 签名篡改、旧 epoch、取消任务、快照外证据被拒绝；协议错误不会变成空结果。
7. 真实 HTTP 工具能被 LangGraph 编译并调用；原生技能可以发现、读取，`.env` 和写文件不可访问。
8. 候选记忆确认前不生效；编辑确认后冻结到新任务；偏好清空不改写旧任务。
9. 连续问答传入同报告最近六轮，跨报告会话被拒绝；并发占用返回冲突，原报告 hash 不变。

## 真实服务与模型

[最终原始记录](phase-7-live.json) 的 **6 组场景全部通过**：六工具实际 HTTP 调用与取消拒绝，
以及 PG 跨进程批准、拒绝、取消、修改和真实多 Agent 综合闭环。

验收脚本创建随机命名的 PostgreSQL 和 Milvus 数据库，导入 9 条证据，真实索引同步 `done=9, failed=0`。
MCP 服务和每次 Worker 执行分别启动子进程；批准后的 Worker 没有原进程内存，只能依靠 PG 检查点恢复。
脚本结束后已清理专属临时库。原始记录中的运行 ID 属于临时库，用于审计，不是用户业务库中的可打开报告。

真实配置：聊天 `qwen3.7-plus`，向量 `text-embedding-v4`。最终研究运行：

- 13 次聊天调用、17 次工具调用；输入 46,059 token，输出 4,955 token。
- 记录包含 `read_file`、两次 `task` 专项委派、评论/规则查询、证据回查和本地研究笔记。
- 随后另做两次真实报告追问；它们独立于上述研究预算，回答保存在原始记录中。
- 这是 multi 模式的实际开销示例；个人日常演示可以使用默认 workflow，避免无必要的多 Agent 调用。

初次完整试运行已通过工程链路，但抽查发现回答把“装汤”扩写成“热汤”。
[初次记录](phase-7-live-initial.json) 保留该问题，没有覆盖成成功答案。
随后补充技能与追问提示，强调不得推断未记录的温度。最终复验回答明确区分“冷水静置桌面”和“装汤背包倾斜”，
没有再补出“热汤”。**这只是该样例的人工抽查结果，不代表所有模型结论都已获得语义正确性保证。**

## 限制与未宣称的结果

- 本期是本地单用户应用；没有多租户鉴权，不应直接部署到公网。
- auto 复核基于缺失字段和冲突关键词，不是完整的事实判断器；重要研究可选 always。
- 原生技能是研究方法，不保证模型逐字遵守；引用合法性与证据语义支持是两回事。
- 候选偏好机制已用可控模型响应验证，真实模型是否提出候选取决于具体问题，未宣称每次都会产生。
- 继承第六期限制：独立人工引用支持率评分、Word 打印版式、全新操作系统安装尚未新增验收。
- 共享 py12 中既有的两组无关包冲突仍在依赖报告记录；没有修改它们。
- 本次新增真实测试直接启动 Worker 执行函数的独立进程；Celery/Redis 消息队列故障测试沿用第四期，不宣称本期重新完成全部队列故障实验。
