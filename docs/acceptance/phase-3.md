# 第三期验收报告

日期：2026-10-21。分支：`codex/v3`。环境沿用 py12、真实 PG/Milvus 和已配置的兼容模型服务。

## 功能交付

两个专项 Deep Agent、运行内持久笔记、规则/评论独立向量集合、
轻量关键词与向量 RRF、市场/品类/商品过滤、版本回查、更新与软删除、
事务索引 outbox、重试与重建命令。报告提交时拒绝已经失效的证据版本。
操作见 [第三期说明](../phase-3-guide.md)。

## 实测

- 本期单元测试：27 项通过（包括前期回归），ruff 检查通过。
- 真实索引：47 条证据；重放网络失败后的事件，共完成 94 个事件，0 个同步失败。
  两种集合均成功返回带 ID 的真实检索结果。
- 正常研究：`b4ebdbb8-866c-4e61-b688-afa999c859b9`，157.42 秒，
  12 次模型、24 次工具调用，包含两次 task 委派、规则/评论检索、统计和笔记。
- 缺失研究：`91554895-a364-4615-b7ba-64ed94b5d5cf`，24.44 秒，
  3 次模型、4 次工具调用；没有委派，输出缺失销量与竞品数据。
- 冲突研究：复测运行 `f9260c85-517e-4729-9cfb-7b21e18466ba` 完成。
  当前商品没有足够的相反规格评论，结论必须是对比证据不足，不能编造冲突。
- 删除、版本更新、重复事件、集合丢失重建、旧事件晚到、向量空间隔离、
  删除后禁止发布报告与越权工具拦截由隔离单元测试覆盖。

## 失败与限制

首次冲突案例、复测正常案例的 JSON 修复请求发生超时，原始结果保留 `passed=false`。
复测并非全部一次通过；不能据此宣称稳定性达到生产标准。
已定位未转义引号问题，修复调用使用 JSON 输出模式，纯 Markdown 围栏在本地移除。
每次执行最多修复一次，整体仍受持久模型调用次数预算限制。

首次正常研究将合成规则写成了市场要求，属于语义质量错误，虽然引用可解析。
提示词已明确要求合成规则只能称“样例核验清单”，并限制摘要与声明长度。
这不是经过人工统计的引用支持率；第六期应将其作为错误案例，不宣称 100% 正确。

真实样例规模小，不足以证明多 Agent 比固定流程效果更好；调用成本明显高于缺失直答。
索引更新与删除逻辑通过隔离仓储测试，本期未在用户的真实证据上执行破坏性删除实验。
旧版第一期规则接口仍保留，第三期分析应使用 `multi` 与 `/api/evidence/search`。
