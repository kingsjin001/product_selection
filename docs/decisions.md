# 选型与面试讨论记录

## 保留 Deep Agents 和 Milvus

这两项是项目约束。Deep Agents 用于工具选择和专项委派，外层仍由 LangGraph
固定研究、计算、校验和保存阶段。这样可以直接比较自主研究与固定检索综合，
也能把成本和状态写入控制留在确定性代码中。

Milvus 使用 MilvusClient，规则与评论分集合，并以模型/维度隔离索引。
业务事实仍在 PostgreSQL：删除、版本和快照过滤不会仅依赖向量库最终一致性。
当前数据量很小，选择 Milvus 是为实现和展示向量检索生命周期，
没有证据表明它比更轻量方案更适合这组 56 条评测证据。

## 默认固定检索综合，按需自主研究

第六期 A/B/C 各完成三个商品。B 总聊天输入/输出为 4205/5067 token，
A 为 13285/5743，C 为 25007/3566；默认入口因此选择 B，
同时保留 C 供冲突、多规格和补查问题使用。

这是端到端策略比较：A 包含同市场全部冻结规则，B/C 检索再按品类过滤，
不能将 token 差异全部归因于 Agent 本身。C 本组没有委派子 Agent，
且每方案只有三次，不能声称子 Agent 提升质量或稳定降低延迟。
第三期专项轨迹和失败案例另外保留。

## PostgreSQL + outbox + Celery

把“创建任务”和“消息成功投递”拆成两个可恢复步骤，避免数据库提交后 Redis
暂时不可用导致任务消失。消息可以重复，Worker 用领取状态和 epoch 保证迟到执行
无法覆盖结果。这个设计不承诺模型请求严格只发生一次。

Redis 仅作 broker；报告、事件和检查点不依赖 Redis 长期保留。
Windows 使用 Celery solo 便于本机调试；生产并发、Linux 进程池和容量评估属于后续工作。

## 引用可解析不等于论据成立

程序可校验 ID、版本、有效性和快照一致性，不能据此宣称语义支持率达标。
43 个声明/证据关系已整理为人工表，判断栏留空。真实的人工复核应由独立评审者
检查是否支持、是否混淆条件、是否遗漏反例，再解盲比较方案。

合成冲突案例同时改变容积、温度和倾斜状态；报告只能描述条件差异。
没有商品销量或市场规模数据时，不输出虚构销量、规模或预测。

## 成本计算和报告不可变

贡献利润用 Decimal、显式成本和固定版本公式计算；费用零值必须由使用者明确提供。
模型负责组织证据和说明缺失。成本更改产生新报告，追问单独记录，
便于面试中现场说明“为何前后数字不同”和“原报告是否被覆盖”。

导出复用报告源且不调用模型。Word 结构、数值和引用经过检查，
缺少可用渲染器导致打印版式尚未验收，不能以 docx 文件存在代替视觉质量。

## 有意保留的边界

没有可用的真实商品 API 授权，因此保留 CSV/JSONL 导入路径。
没有引入第三个模型供应商、自动爬虫、图像分析或全自动选品采购。
没有账户实际单价，费用仅保留 token 和可补填的价格表，未知不填零。
没有为修复本项目之外的 pip 冲突擅自更改共享 py12 包版本。

下一步最有价值的验证是：独立标注更大的真实授权语料、更多市场/品类候选、
多次重复试验及账户单价；随后再考虑复杂检索、更多 Agent 或生产部署。
这些是下一阶段建议，不是本次已完成的收益。
